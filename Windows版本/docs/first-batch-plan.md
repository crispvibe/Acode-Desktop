# acode Windows First Batch Plan

## Scope

The first batch is accepted as six modules. Each module must keep the Electron main, preload, renderer, and shared contracts separate, and must leave package validation reproducible from scripts.

| Module | Owner area | Acceptance |
| --- | --- | --- |
| 1. Electron shell | `src/main` | Main window starts from `dist/main/main.js`, loads `dist/preload/preload.cjs`, and keeps `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`, and `webSecurity: true`. |
| 2. Preload bridge | `src/preload` | Preload exposes only `window.acode` through `contextBridge.exposeInMainWorld("acode", ...)`; renderer does not receive raw Electron or Node objects. |
| 3. Shared IPC contracts | `src/shared` | Channel names and DTO validation are centralized, typed, and reused by main and preload. |
| 4. Renderer workbench | `src/renderer` | The first UI shell renders the project sidebar, editor area, chat panel, settings entry, and window controls without requiring Node access in renderer. |
| 5. Packaging config | `package.json`, `dist/**`, `release/**` | Build output contains `dist/main/main.js`, `dist/preload/preload.cjs`, and `dist/renderer/index.html`; Windows artifacts are generated by the Windows runner for signed installer validation. |
| 6. Acceptance and docs | `scripts/**`, `docs/**` | Smoke validation checks required artifacts, Electron security strings, and the preload `window.acode` bridge before handoff. |

## Local Acceptance Commands

Run from `Windows/`:

```bash
npm run typecheck
npm run build
npm run lint:smoke
```

Do not run `npm run dist:win` on this worker. That command is reserved for the Windows packaging runner.

## Windows Runner Acceptance

The Windows runner must use the same committed source and lockfile, then record:

| Gate | Command or evidence |
| --- | --- |
| Build | `npm ci`, `npm run build`, `npm run lint:smoke`, then `npm run dist:win` on Windows. |
| Artifact inventory | `release/acode-Setup-<version>-x64.exe`, `release/acode-Portable-<version>-x64.exe`, `release/win-unpacked/Codevoke.exe`, and `builder-effective-config.yaml`. |
| Code signing | `Get-AuthenticodeSignature release\\acode-Setup-<version>-x64.exe` and `signtool verify /pa /v release\\acode-Setup-<version>-x64.exe`; repeat for portable and `win-unpacked\\Codevoke.exe` when signing is enabled. |
| Installer smoke | Install NSIS on a clean Windows VM, launch acode, verify first window render, close, uninstall, and confirm user data is preserved unless an explicit uninstall-cleanup mode is selected. |
| Portable smoke | Launch the portable EXE from a non-admin user profile, verify first window render, close, and relaunch. |
| SmartScreen | Download the signed installer through the intended distribution path on a clean Windows VM, capture first-run reputation behavior, publisher display name, certificate chain, and any SmartScreen warning text. |
| Logs | Preserve runner logs, signing output, installer screenshots, and first-launch app logs as release evidence. |

## Release Notes Inputs

The first batch release note must list the six modules above, the exact commit, artifact checksums, signing certificate identity, Windows runner version, and any SmartScreen reputation caveat.
